# Wavo live security/performance changes (2026-10-25)

These SQL migrations were **applied to production** using the connected Supabase migration service after the owner's request to fix Wavo. Their names/versions match the **actual** Supabase migration history; do not replay them by hand.

## Applied

1. `20261025140759_wavo_harden_signup_internal_metadata.sql`: A user-controlled `raw_user_meta_data.is_internal` value or `test:` display-name prefix no longer sets `profiles.is_internal`. Trusted server-managed `raw_app_meta_data` alone controls this property. Signup username formatting and recovery workflow preserved.
2. `20261025140921_wavo_guard_profile_privileged_fields.sql`: New INSERT/UPDATE triggers protect trusted client profile fields. Existing paid-plan and admin protection triggers are retained.
3. `20261025141126_wavo_optimize_auth_rls_and_remove_duplicate_message_index.sql`: 13 RLS policies have per-statement `(select auth.uid())` wrappers with the original authorization expressions retained, and a duplicate `messages(chat_id,created_at)` index has been removed.

## Verification

- Supabase returned `success:true` for each migration.
- Re-read installed signup function: only trusted app metadata controls `is_internal`, and `test:` prefix cannot confer privileges.
- Both new profile field-protection triggers exist and run as SECURITY INVOKER.
- Post-change profile count: 33. Internal profiles: 7; admins: 2. These rows were not modified.
- Confirmed `idx_messages_chat_created` remains, `messages_chat_id_created_at_idx` is gone.
- Supabase Performance Advisor `auth_rls_initplan` count decreased **89 → 76**. Other warnings remain; these are not all vulnerabilities.
- The older synthetic tests in the security review passed, but there has **not** been a comprehensive authenticated-client integration smoke test on iPhone/browser.
 
## Still open: broad profile reads

The `profiles readable` SELECT policy still permits any signed-in user to read **all** columns, including `stripe_customer_id`, birthday, and payment/account flags. This risk is **not fixed** by the triggers above, because RLS does not offer per-column protection. Tightening column grants before the app's `select('*')` calls and older iOS clients are migrated would break existing screens. The remedy requires changing browser/iOS profile reads to explicit safe columns and adding a protected self-profile endpoint, then coordinating deployment and SQL grants. Do not claim Wavo profile privacy is resolved.

Supabase Pro branching is unavailable on this account, so changes were limited to narrowly scoped migrations and read-back verification. A full end-to-end staging test was not completed.

## Supabase Auth leak-password checks

Leaked-password detection still requires Auth settings access and has not been enabled by these SQL changes.

## Other advisor findings

- 12 anon-invocable SECURITY DEFINER functions: avoid blanket REVOKE as many are referenced by active RLS policies; review independently.
- 25 unindexed foreign keys: evaluate using workloads before installing indexes indiscriminately.
- 13 policyless RLS tables: some are intentionally service-only and should not get public grants.

## Deployment safety

This PR intentionally contains no production-deployed frontend code. The SQL versions have already been executed by Supabase. Do not merge unrelated feature work as part of security incident response.
